# Backend — текущее состояние

> Единственный источник — реальный код `E:\ProjectMM\backend` на 2026-07-22, не старые файлы `docs/`. Расхождения со старой документацией отмечены явно.

## Архитектура запуска

`server.js`: `dotenv.config()` → **синхронный побочный эффект `initDB.js`** при каждом старте (подключение к MySQL + `CREATE TABLE IF NOT EXISTS` для всех таблиц, кроме `users`) → `express.json()` → CORS (жёсткий whitelist `['http://localhost:3001','https://mindandmotion.ru']`, не из env) → глобальный лог-мидлвар (печатает **весь `req.body` для всех запросов, включая пароли** — см. [[Технический-долг-backend]]) → монтирование роутеров → `app.listen(PORT)`.

**Порт:** `process.env.PORT || 3000`. ⚠️ **Расхождение со старой документацией**: `docs/ARCHITECTURE.md` и корневой `CLAUDE.md` (до этой сверки) указывали дефолт/локальный порт как 5000 — в `.env` бэкенда переменной `PORT` вообще нет, значит фактический локальный порт **3000**. Это тот самый рассинхрон, который минимум раз ронял прод (nginx проксировал на 5000, PM2 слушал 3000) — см. [[Между-файлами-эволюция-во-времени]].

**БД:** `db.js` — пул `mysql2/promise`, `connectionLimit: 10`, **`timezone: '+00:00'`** (все TIMESTAMP — UTC).

**Env-переменные, реально используемые кодом:** `DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, JWT_SECRET, EMAIL_HOST, EMAIL_PORT, EMAIL_USER, EMAIL_PASS, EMAIL_FROM, EMAIL_FROM_NAME`. Больше ничего (нет `NODE_ENV`, нет отдельного `FRONTEND_URL`).

## API — полный список эндпоинтов (по факту кода)

Все монтируются под `/api` (в т.ч. auth — `POST /api/login`, не `/api/auth/login`).

| Домен | Роуты |
|---|---|
| **Auth** (`routes/auth.js`, публичные) | `POST /register` (легаси, без верификации email), `POST /login`, `POST /send-verification-code`, `POST /verify-code`, `POST /forgot-password`, `POST /reset-password` |
| **User** (`/api/user`) | `GET /profile`, `PUT /profile`, `PUT /password`, `DELETE /demo-data` |
| **Tasks** (`/api/tasks`) | `GET /`, `GET /stats`, `GET /date`, `GET /overdue`, `POST /sync` (офлайн-upsert), `POST /delete`, `POST /`, `PUT /:id/stop-recurring`, `PUT /:id` (авто-генерация следующей повторяющейся задачи), `POST /:id/focus`, `DELETE /:id` |
| **Subtasks** (`/api/tasks/:taskId/subtasks`, `/api/subtasks`) | `GET /`, `POST /`, `PUT /:subtaskId`, `DELETE /:subtaskId`, `PUT /:id/toggle` — ⚠️ см. [[IDOR-подзадачи]] |
| **Habits** (`/api/habits`) | `GET /`, `PUT /reorder`, `GET /records/:year/:month`, `POST /records`, `DELETE /records` (body и params-варианты), `POST /`, `PUT /:id/monthly-config`, `PUT /:id/archive`, `PUT /:id`, `DELETE /:id` (мягкая архивация при `?year&month`, иначе полное удаление) |
| **Folders** (`/api/folders`) | `GET /`, `POST /`, `PUT /reorder`, `PUT /:id`, `DELETE /:id` |
| **Birthdays** (`/api/birthdays`) | `GET /`, `POST /`, `DELETE /:id` — нет `PUT` |
| **Policies** (`/api`) | `POST /policies/accept`, `GET /announcements`, `POST /announcements/:id/read` |
| **Secret Chat** (`/api/secret-chat`) | `GET /`, `POST /login`, `POST /`, `POST /tomato`, `POST /punish`, `PUT /settings`, `GET /users`, `PUT /rank`, `POST /clear` — все админ-операции завязаны на `userId===4`, см. [[Технический-долг-backend]] |

Паттерн ошибок: валидация → 400; not found/нет доступа → 404/403; остальное → 500 (иногда с `err.message`/`err.sqlMessage` наружу).

**Важный паттерн кода**: специфичные роуты (`/reorder`, `/sync`, `/records`, `/date`, `/overdue`, `/stats`, `/:id/stop-recurring`, `/:id/archive`) везде явно закомментированы разработчиками как обязанные идти **выше** `/:id` — сохранять этот порядок при добавлении новых роутов.

## Схема БД (полный список таблиц)

Создаются в `initDB.js` при каждом старте (`CREATE TABLE IF NOT EXISTS`), кроме `users` — **её DDL нет в репозитории вообще**, структура выведена из фактически используемых полей в routes.

**Активно используемые:** `tasks`, `habits`, `habit_records` (UNIQUE `user_id,habit_id,year,month,day`), `email_verifications`, `habit_monthly_configs` (UNIQUE `habit_id,year,month`), `subtasks`, `folders`, `secret_chat_settings`, `secret_chat_user_meta`, `announcement_reads` (⚠️ без уникального ключа, хотя код рассчитывает на `INSERT IGNORE`), `app_announcements`, `birthdays` (поля `type`/`notify_before` в схеме есть, в роуте не используются), `password_resets`, `secret_chat_messages`.

**Мёртвые таблицы (создаются, но ни один route их не использует):** `chat_settings`, `secret_chat` (старая версия), `message_reactions`, `email_logs`. См. [[Технический-долг-backend]].

Сущности как TypeScript-интерфейсы — см. [[06-Домен/Сущности|Домен]].

## Аутентификация

`middleware/auth.js`: `Authorization: Bearer <jwt>`, секрет `process.env.JWT_SECRET`, **c небезопасным хардкод-фолбэком `'your-secret-key-12345'`** (дублируется в 3 местах) — см. [[JWT-секрет-фолбэк]]. Payload — только `{ userId }`, TTL 30 дней, кладётся в `req.userId`. Нет проверки существования пользователя на каждый запрос, нет ролевой модели (кроме хардкода `userId===4` для secret chat).

## Email-сервис

`nodemailer` + SMTP Beget. `tls: { rejectUnauthorized: false }` с комментарием "для тестирования" — см. [[Технический-долг-backend]]. Функции-шаблоны `getVerificationEmailHtml`/`getWelcomeEmailHtml` существуют, но `routes/auth.js` дублирует HTML инлайн вместо их использования. Welcome-письмо содержит захардкоженную ссылку на **прод-IP** (не домен).
