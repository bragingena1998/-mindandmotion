# Домен Mind & Motion — сущности

> Единый источник по типам данных для backend/mobile/web. При изменении схемы БД или контракта API — обновлять этот файл.

## Task (Задача)

```typescript
interface Task {
  id: number;
  user_id: number;
  title: string;              // VARCHAR(500) NOT NULL
  date: string | null;        // DATE, 'YYYY-MM-DD'
  time: string | null;        // VARCHAR(5), 'HH:MM'
  deadline: string | null;    // DATE
  priority: 0 | 1 | 2 | 3;    // DEFAULT 2
  comment: string | null;
  done: boolean;              // DEFAULT FALSE
  done_date: string | null;
  focus_sessions: number;     // DEFAULT 0
  is_recurring: boolean;
  recurrence_type: string | null;
  recurrence_value: string | null;
  is_generated: boolean;
  template_id: number | null;
  folder_id: number | null;
  subtasks_count: number;     // денормализованный счётчик, добавлен миграцией
}
```

⚠️ Реальные имена колонок в БД — `snake_case` с подчёркиванием (`is_recurring`, `recurrence_type`, `done_date`, `folder_id`) — подтверждено чтением `initDB.js` (2026-07-22). Старые правила (`.windsurf/rules/03-backend.md`) описывали защитные цепочки вида `task.isrecurring` (без подчёркивания) как альтернативный вариант от бэкенда — возможно, отражение более старой версии схемы. Адаптеры на клиенте по-прежнему стоит писать максимально защитно (`??`-цепочки на оба варианта), пока не будет проведена явная проверка, действительно ли бэкенд когда-либо отдавал бесподчёркивающий вариант.

**Вычисляемые статусы** (не хранятся в БД): `overdue` (date < сегодня, done=0), `today`, `future`, `completed` (done=1), `no_date`.

**Приоритеты:** 1=ВЫСОКИЙ (danger/красный), 2=СРЕДНИЙ (accent/золотой), 3=НИЗКИЙ (ok/зелёный). 0 = нет приоритета.

## Habit (Привычка) и HabitRecord

```typescript
interface Habit {
  id: number;
  user_id: number;
  name: string;
  unit: string | null;               // 'мин', 'км', 'раз'; DEFAULT 'раз'
  plan: number;                      // DEFAULT 0
  target_type: 'daily' | 'weekly' | 'monthly'; // DEFAULT 'monthly'
  start_date: string | null;
  end_date: string | null;
  days_of_week: number[] | null;     // JSON-массив в БД; 0=пн...6=вс
  order_index: number;
  start_year: number | null;         // добавлено миграцией
  start_month: number | null;        // добавлено миграцией
}

interface HabitRecord {
  id: number;
  user_id: number;
  habit_id: number;
  year: number;
  month: number;   // 1-12
  day: number;     // 1-31
  value: string;   // VARCHAR(255) DEFAULT '0' — хранится строкой, парсить как float на клиенте
}

interface HabitMonthlyConfig {   // habit_monthly_configs, UNIQUE(habit_id, year, month)
  habit_id: number;
  year: number;
  month: number;
  plan: number | null;
  unit: string | null;
  is_archived: boolean;
}
```

⚠️ `habit_records.value` в БД — `VARCHAR`, не числовой тип. `daysOfWeek` парсится на web в 4 разных форматах (JSON-массив / Postgres-литерал `{1,2,3}` / CSV-строка / число) — см. [[03-Web/Текущее-состояние]] — признак нестабильности контракта во времени, не факт, что все 4 формата реально приходят сейчас.

**Архивация** — не удаление, а `habit_monthly_configs.is_archived=1` для конкретного месяца (`PUT /habits/:id/archive` с `year`/`month`).

**Отображение ячейки:** если `unit` есть → числовое значение (`value/plan`), иначе → ✓/пусто. `value >= plan` → выполнено.

## Birthday (День рождения / Событие)

```typescript
interface Birthday {
  id: number;
  user_id: number;
  name: string;
  day: number;
  month: number;
  year: number | null;
  type: string;            // DEFAULT 'birthday' — колонка есть, но routes/birthdays.js её не использует
  notify_before: number;    // DEFAULT 1 — колонка есть, но routes/birthdays.js её не использует
}
```
⚠️ `type` и `notify_before` — задел на будущее в схеме БД, не реализованный на уровне API (`routes/birthdays.js` работает только с `name/day/month/year`). Нет `PUT /birthdays/:id` — только GET/POST/DELETE.

## User

DDL таблицы `users` отсутствует в репозитории — `initDB.js` только читает/ALTER-ит её. Известные поля по факту использования в routes: `id, email, password, name, birthdate, gender, email_verified, privacy_accepted, terms_accepted, email_marketing_accepted, policies_accepted_at, created_at`.

## snake_case ↔ camelCase — защитные цепочки (обязательный паттерн на клиенте)

```js
task.folderId      ?? task.folder_id      ?? null
task.isRecurring   ?? task.is_recurring   ?? task.isrecurring ?? 0
task.doneDate      ?? task.done_date      ?? null
task.subtasksCount ?? task.subtasks_count ?? 0
habit.targetType   ?? habit.target_type   ?? 'daily'
habit.startDate    ?? habit.start_date    ?? null
habit.daysOfWeek   ?? habit.days_of_week  ?? null
```

## Вычисляемые функции (общие для клиентов)

```js
function getTaskStatus(task) {
  if (task.done) return 'completed';
  if (!task.date) return 'no_date';
  const today = new Date().toISOString().split('T')[0];
  if (task.date < today) return 'overdue';
  if (task.date === today) return 'today';
  return 'future';
}
```
