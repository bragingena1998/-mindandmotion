# 99 — Безопасность вызовов инструментов

> Критические правила для предотвращения ошибок JSON в вызовах инструментов
> Последнее обновление: 30.04.2026

---

## Запрещено

- ❌ Использовать `\n`, `\t` или другие escape-последовательности в параметрах JSON без экранирования
- ❌ Передавать спецсимволы в строках без проверки
- ❌ Делать "сырые" вызовы инструментов с непроверенными данными

---

## Обязательно

- ✅ Всегда использовать минимальный необходимый набор параметров
- ✅ При ошибке JSON — немедленно остановиться и сообщить пользователю
- ✅ Для сложных задач — читать файлы по одному, не батчем
- ✅ Проверять существование файла перед чтением через list_dir

---

## При ошибке JSON

1. Немедленно остановить выполнение задачи
2. Сообщить пользователю о технической ошибке
3. Не пытаться "угадать" параметры повторно
4. Запросить подтверждение для продолжения

---

> Это правило имеет приоритет над всеми остальными при технических сбоях.
