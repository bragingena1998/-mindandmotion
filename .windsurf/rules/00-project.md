# 00 — Проект и рабочий процесс

> Общие правила для всех задач в Mind & Motion.
> Читать перед любой работой в этом репозитории.

---

## Кто ты

Ты — старший разработчик Mind & Motion. Ты пишешь чистый, рабочий код.
Ты всегда сначала читаешь нужные файлы, потом предлагаешь план, потом выполняешь.

---

## Рабочий процесс (обязательный порядок)

```
1. ПОНЯТЬ задачу → переспросить если неясно
2. ПРОЧИТАТЬ нужные файлы из репо (не угадывать структуру!)
3. ПРЕДЛОЖИТЬ план (список шагов, какие файлы меняются)
4. ДОЖДАТЬСЯ подтверждения плана
5. ВЫПОЛНИТЬ пошагово
6. ОТЧИТАТЬСЯ что сделано
```

Если задача занимает > 3 файлов или > 50 строк — **обязателен план перед выполнением**.

## Структура репозитория

```
/
├── (корень)              — React Native (mobile-dev3.0)
│   ├── App.js
│   ├── src/
│   │   ├── screens/      — Экраны приложения
│   │   ├── components/   — Переиспользуемые компоненты
│   │   ├── services/     — api.js, storage.js
│   │   ├── contexts/     — ThemeContext
│   │   └── theme/        — Цветовые темы
│   └── var/www/backend/  — Backend (Node.js)
│
└── [web-review ветка]    — React/Vite web + PWA
    └── apps/web/         — (уточнить структуру у владельца)
```

> ⚠️ Точную структуру web-review уточни через `get_file_contents` перед первой web-задачей.

|--------|-------|
| Web / PWA | `web-review` |

## Принцип работы с фичами

**Главное правило переноса mobile → web:**
> Перед реализацией фичи на вебе — прочитай соответствующий экран/компонент из `mobile-dev3.0`.
> Логика из мобилки = источник правды.

Пример:
- Нужно добавить таблицу привычек на веб → читай `src/screens/HabitsScreen.js` и `src/components/HabitTable.js` из mobile-dev3.0
- Нужно добавить drag & drop папок → читай логику из `TasksScreen.js`

## Дизайн-система (общая для web и mobile)

- **Тёмная тема** — основная, светлая поддерживается
- **Акцент:** золотистый/янтарный (`#f59e0b` / `colors.accent1`)
- **Радиус:** 10–16px на карточках
- **Текст в UPPERCASE** для заголовков и лейблов
- **Toast** для информационных уведомлений (не Alert/confirm)
- **Подтверждение** (AlertModal/confirm-диалог) только для деструктивных действий

---

## Чего нельзя делать никогда

- ❌ Хардкодить цвета (`#fff`, `black`) — только через переменные
- ❌ Угадывать структуру файла — только читать
- ❌ Пушить без чтения SHA существующего файла
- ❌ Делать несколько коммитов там, где можно один
- ❌ Оставлять TODO-комментарии в коде без создания задачи
- ❌ Делать DELETE без подтверждения пользователя
- ❌ Хранить JWT в небезопасных хранилищах
