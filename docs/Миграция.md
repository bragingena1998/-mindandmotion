### Изменяемые файлы (рефакторинг)

| Текущий файл | Изменение | Риск |
|--------------|-----------|------|
| `mindandmotion-mobile/src/services/api.js` | Импорт из `packages/shared` | Зависимость от нового пакета |
| `mindandmotion-mobile/src/screens/TasksScreen.js` | Удалить inline `tasksAPI`, использовать shared | ~200 строк адаптации |
| `habits-app/tasks-api.js` | Полностью заменить на shared client | Сломает текущий web |
| `mindandmotion-mobile/App.js` | Унифицировать `BASE_URL` | Конфликт IP vs домен |

### Риски Фазы 1

1. **API URL конфликт**: Mobile использует `85.198.96.149:5000`, web — `mindandmotion.ru`
   - *Митигация*: Вынести в env-переменные, создать `.env.example`

2. **Токен storage inconsistency**: Web использует `localStorage`, mobile — `AsyncStorage` + `SecureStore`
   - *Митигация*: Абстракция `StorageAdapter` в shared с platform-specific реализациями

3. **Регресс mobile**: Рефакторинг 2249-строчного `TasksScreen.js` опасен
   - *Митигация*: Пошаговый перенос, сохранение старых импортов как fallback

4. **Отсутствие TypeScript**: Текущий код JS, shared будет TS
   - *Митигация*: Начать с JSDoc, постепенная миграция

### Оценка приоритета: ВЫСОКИЙ (блокер для остальных фаз)
- **Польза**: Устраняет дублирование ~800 строк кода, унифицирует API
- **Риск**: Средний (только создание новых файлов, минимум изменений в существующих)
- **Соотношение**: 10/3 — Начинать немедленно

### Риски Фазы 2

1. **Feature parity gap**: Mobile имеет 13 экранов, web нужно минимум 5 основных
   - *Митигация*: Приоритизация: Tasks → Habits → Dashboard → Calendar → Profile

2. **Drag-and-drop**: Mobile использует `react-native-draggable-flatlist`
   - *Митигация*: `@dnd-kit/core` или `react-beautiful-dnd` для web

3. **Gestures**: Swipe-to-complete в mobile (React Native Gesture Handler)
   - *Митигация*: Для web — кнопка "Выполнить" + hover-меню (нет свайпов на desktop)

4. **State persistence**: Mobile использует `expo-sqlite`, web нужен IndexedDB
   - *Митигация*: `idb` package или `localforage` в `tasksStore.ts`

5. **SEO**: Dashboard/Tasks не нуждаются в SEO, но Terms/Privacy — да
   - *Митигация*: Next.js с SSR для статичных страниц или редизайн

### Оценка приоритета: СРЕДНИЙ
- **Польза**: Замена legacy web, единый UX с mobile
- **Риск**: Высокий (полная реализация UI с нуля ~2-3 недели)
- **Соотношение**: 8/7 — Выполнять после стабилизации Phase 1

## Фаза 3: PWA + Mobile Web Parity

**Цель:** Добавить offline-support, push-уведомления, иконки для PWA

### Создаваемые файлы

| Файл | Назначение | Технология |
|------|------------|------------|
| `apps/web/public/manifest.json` | PWA manifest | Web App Manifest |
| `apps/web/public/sw.js` | Service Worker | Workbox |
| `apps/web/public/icons/` | Иконки 192x192, 512x512 | PNG/WebP |
| `apps/web/src/hooks/useOfflineSync.ts` | Offline queue (аналог `syncQueue.js`) | Background Sync API |
| `apps/web/src/hooks/usePushNotifications.ts` | Push-уведомления | Push API + сервис-воркер |
| `apps/web/src/utils/indexedDB.ts` | IndexedDB wrapper (SQLite alternative) | `idb` package |

### Изменения в backend

| Файл | Изменение | Причина |
|------|-----------|---------|
| `backend/server.js` | Добавить VAPID ключи для Web Push | Push API требует публичный ключ сервера |
| `backend/routes/notifications.js` | Новый роут для подписки/отписки | Web Push subscriptions |

### Риски Фазы 3

1. **Push notifications**: Web Push API ≠ Expo Notifications
   - *Митигация*: Firebase Cloud Messaging или standalone push-сервис

2. **Background sync**: Не все браузеры поддерживают
   - *Митигация*: Graceful degradation — "Sync when online" button

3. **iOS limitations**: iOS Safari не поддерживает все PWA-фичи до 16.4+
   - *Митигация*: iOS users → use native app (redirect)

4. **Storage limits**: IndexedDB ограничен (~50MB), SQLite на mobile — нет
   - *Митигация*: LRU cache, хранить только активные задачи локально

### Оценка приоритета: НИЗКИЙ (но стратегически важен)
- **Польза**: PWA = нативный опыт без App Store, offline parity
- **Риск**: Высокий (сложность Web Push, iOS ограничения)
- **Соотношение**: 9/8 — После стабильного релиза Phase 2
