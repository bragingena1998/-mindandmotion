percent в stats — прогресс за месяц (daily: total / (plan × activeDays), period: total / plan)

Строки: привычки (habits.map)
Колонки фиксированные слева: Название (swipe → edit/delete)
Колонки скроллящиеся: Единица, План, Дни 1-31
Колонки фиксированные справа: Итог, Процент
Ячейки дней:
Tap: быстрое заполнение (логика зависит от unit)
LongPress: таймер (для 'Часы') или input modal (остальные)
Типы привычек (unit):

'Дни' — toggle ✓ / пусто (значение 0 или 1)
'Часы' — инкремент +1 час при тапе, таймер при long press
'Кол-во' и др. — daily: toggle 0/plan, period: инкремент +1
Периоды:

target_type: 'daily' — план "в день"
target_type: 'period' или 'monthly' — план "за период/месяц"
ReorderHabitsModal — есть! Drag-and-drop сортировка, сохранение через PUT /habits/reorder с массивом {id, order_index}.

Точные имена полей в БД (snake_case):
Таблица habits:

id INT PK
user_id INT FK
name VARCHAR(255)
unit VARCHAR(50) DEFAULT 'раз'
plan INT DEFAULT 0
start_year INT          -- добавлено миграцией
start_month INT         -- добавлено миграцией
order_index INT DEFAULT 0  -- добавлено миграцией
target_type VARCHAR(20) DEFAULT 'monthly'  -- 'daily' | 'monthly' | 'period'
start_date DATE DEFAULT NULL
end_date DATE DEFAULT NULL
days_of_week TEXT DEFAULT NULL  -- JSON "[0,1,2]"
created_at TIMESTAMP
Таблица habit_records:

id INT PK
user_id INT FK
habit_id INT FK
year INT
month INT
day INT
value INT DEFAULT 0
updated_at TIMESTAMP
UNIQUE KEY (user_id, habit_id, year, month, day)
Таблица habit_monthly_configs (архивация + настройки месяца):

id INT PK
habit_id INT FK
year INT
month INT
plan INT DEFAULT 0
unit VARCHAR(50)
is_archived BOOLEAN DEFAULT FALSE
created_at TIMESTAMP
UNIQUE KEY (habit_id, year, month)
Хранение прогресса:
Отдельная таблица habit_records — одна строка = одна ячейка (habit × day)
UPSERT логика: INSERT ... ON DUPLICATE KEY UPDATE value = VALUES(value)
Удаление = DELETE FROM habit_records WHERE ...
Фильтрация:
GET /habits с ?year=&month= фильтрует привычки активные в этом месяце:
sql
(h.start_year < ? OR (h.start_year = ? AND h.start_month <= ?))
AND NOT EXISTS (SELECT 1 FROM habit_monthly_configs WHERE is_archived = 1)

Нестандартные нюансы (не похоже на Tasks):
Таблица-сетка — Tasks это список, Habits это матрица (rows × cols) с фиксированными колонками по бокам и горизонтальным скроллом дней
Два параллельных запроса — habits и records загружаются отдельно, мерджатся на фронте. Нужен Promise.all или два useEffect
Оптимистичные обновления — при тапе на ячейку сначала меняем локальный стейт records, потом шлём API. Нужна функция optimisticUpdateRecords аналогичная мобиле
Разная логика тапа по unit — Дни: toggle, Часы: +1, остальное: daily=toggle plan, period=+1
Таймер для 'Часы' — long press открывает таймер, который можно "свернуть" (работает в фоне через localStorage)
Дни недели и периоды — привычка может быть активна только в определённые дни или даты (start_date-end_date). Нужна функция isDayActive
Архивация — привычки не удаляются, а архивируются для конкретного месяца через habit_monthly_configs
Порядок (order_index) — drag-and-drop сортировка привычек, сохраняется отдельным API вызовом
Статистика на лету — "Итог" и "Процент" считаются на фронте из records × plan × activeDays
