# Прод недоступен: MySQL блокирует подключения с VPS

**С 2026-07-23 ~05:49 UTC бэкенд не может подключиться к MySQL** (`kukopoocheypot.beget.app:3306`). Ошибка на уровне TCP — `Connection refused`, не уровня авторизации. Подтверждено запросом в обход Node.js (`/dev/tcp/...` напрямую с VPS) — соединение отклоняется до какой-либо аутентификации.

## Как обнаружено

После планового деплоя backend (пересборка git-репозитория на сервере, см. [[08-Решения/История-решений]]) тестовый `POST /api/login` вернул `500` вместо ожидаемого `400`. В логах — сначала `ER_ACCESS_DENIED_ERROR`, затем `ECONNREFUSED 85.198.97.167:3306`.

## Рабочая гипотеза

Деплой сам по себе не виноват — `db.js` (файл с логикой подключения) не менялся вообще между старой и новой версией (побайтово идентичен). Вероятная причина: в тот же день пароль от MySQL был сменён (плановая ротация секретов после утечки `context-perplexity/`, см. [[08-Решения/История-решений]]). Старый процесс backend какое-то время продолжал пытаться подключаться со старым паролем (несколько записей `ER_ACCESS_DENIED_ERROR` в логах) — похоже, это спровоцировало временную блокировку IP VPS на стороне Beget/MySQL (типичная защита от подбора пароля).

**Проверено и исключено:** блокировка не в панели Beget → Настройки аккаунта → Безопасность → "Блокировка по IP" — там чёрный список, но пустой ("Нет ограничений по IP-адресам"). Значит блокировка либо на уровне самого MySQL (`max_connect_errors`), либо в отдельном, ещё не найденном месте панели, либо это временная автоматическая мера, которая снимется сама.

## Статус

✅ **Разрешилось само, в тот же день.** Владелец написал в поддержку Beget (ответ ещё не пришёл на момент резолюции). Проверено повторно: TCP-подключение к `kukopoocheypot.beget.app:3306` восстановлено, `mysql -e "SELECT 1"` с паролем из `.env` проходит успешно, живой `POST /api/login` возвращает `400` (не `500`) — весь путь nginx → backend → MySQL снова рабочий.

Подтверждает гипотезу о **временной** автоматической блокировке (не постоянной, не требующей вмешательства поддержки) — сняла себя сама по времени. Пароль в `.env` не менялся повторно, тот же, что был установлен при изначальной ротации секретов, и он рабочий.

**Побочная находка в процессе:** владелец случайно сменил пароль входа в саму phpMyAdmin (не пароль пользователя БД) через "Основные настройки" — не то же самое, что смена пароля MySQL-пользователя. Для смены именно пароля БД — панель Beget → "Базы данных", либо phpMyAdmin → "Учётные записи пользователей", не "Основные настройки".
