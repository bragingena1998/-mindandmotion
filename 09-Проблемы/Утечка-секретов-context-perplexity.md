# КРИТИЧНО: боевые секреты в архиве `context-perplexity/`

В 5 из 11 файлов `E:\ProjectMM\context-perplexity\*.md` в открытом виде вставлены продовые credentials (владелец копировал вывод `.env` и команд прямо в чат с Perplexity):

- `ознакомься с этим чатом полностью. главное увидь ч.md`
- `Привет. Я работаю над своим приложением. Это плане.md`
- `Смотри у меня есть готовое приложение мне необходи.md`
- `смотри я начал перенос дашборда да__вот анализ от.md`
- `у меня есть приложение и я выложил его на рустор,.md`

Типы утекших секретов: пароль MySQL (`DB_PASSWORD`), `JWT_SECRET`, пароль email-аккаунта (`EMAIL_PASS`), `GROQ_API_KEY`, логин/пароль личной почты владельца.

## Риск

`context-perplexity/` — обычная (не submodule) директория, закоммиченная напрямую в суперпроект `E:\ProjectMM` (ветка `landing`, коммит `243a767`). У суперпроекта на 2026-07-22 **не настроен git remote** — секреты пока не запушены никуда через этот репозиторий. Но:
- Секреты уже в локальной истории git этой ветки — простое удаление файлов не поможет, история их всё равно содержит.
- Если когда-либо к этой ветке подключат remote и запушат как есть — секреты утекут на GitHub.

## Статус

**Не устранено на 2026-07-22.** Требуется явное решение и действие владельца:

1. Считать все перечисленные секреты скомпрометированными и ротировать: пароль MySQL-пользователя, `JWT_SECRET` (инвалидирует все текущие сессии пользователей — учитывать при выборе времени), `EMAIL_PASS`, `GROQ_API_KEY`, пароль личной почты.
2. Не добавлять remote к ветке `landing` (или любой другой, содержащей эти коммиты) без предварительной очистки истории (`git filter-repo`/BFG) либо без переноса `context-perplexity/` в `.gitignore` и полного вычищения из истории.
3. Впредь не хранить архивы переписки с секретами в отслеживаемой git-директории.

См. также [[JWT-секрет-фолбэк]] — отдельная, не связанная напрямую, но усиливающая проблема с самим `JWT_SECRET` в коде.
