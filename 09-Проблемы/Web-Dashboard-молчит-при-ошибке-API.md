# Web/Dashboard: ошибка загрузки данных маскируется под "всё пусто"

Когда запросы `fetchTasks`/`fetchHabitRecords` и т.п. падают (проверено на 403 при невалидном токене, но логика та же для любого сбоя сети/API), `Dashboard.tsx` не показывает никакого сообщения об ошибке — вместо этого рендерит обычное пустое состояние: "🎉 Всё выполнено!", "Нет активных привычек. Начни формировать полезные привычки!", статистика — везде нули.

**Проблема:** пользователь не может отличить "у меня правда нет задач" от "сайт не смог загрузить мои задачи". Второе выглядит как первое — вводит в заблуждение, особенно неприятно при реальном сбое сети/сервера (пользователь решит, что всё выполнено, и не будет разбираться, почему).

## Точное место в коде

`Dashboard.tsx:55-57` — `catch (error) { console.error(...) }`, без `setError`/тоста/баннера. `tasks`/`habits`/`habitRecords` по умолчанию `[]` (`Dashboard.tsx:9-11`) — любая ошибка выглядит как "данных нет", а не "не удалось загрузить". CSS для error/retry-состояния в `dashboard.css` вообще отсутствует — этот случай изначально не проектировался.

## Что нужно

Единый паттерн обработки ошибки загрузки для виджетов дашборда (задачи, привычки, статистика, неделя) — как минимум индикатор "не удалось загрузить" + кнопка повтора (`loadData()` уже есть, просто не переиспользуется как retry-хендлер). Согласуется с [[Web-сырая-ошибка-API-на-Задачах]] — оба про то, что `web/` сейчас непоследовательно обрабатывает ошибки API между разными страницами (Habits — норм, Tasks — сырой текст, Dashboard — молчит). См. также [[Web-Dashboard-неверный-расчёт-запланировано]] — отдельный, но смежный баг в той же области.

## Как воспроизвести

Открыть `/` (дашборд) с невалидным токеном или при недоступном бэкенде — все виджеты покажут "пусто", в консоли при этом реальные `AxiosError` на каждый из параллельных запросов (`Promise.all` в `Dashboard.tsx`).
