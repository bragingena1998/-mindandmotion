# После успешного логина web откатывает на страницу входа

Токен после `POST /login` сохраняется корректно (`localStorage`), но пользователь визуально не может войти без ручной перезагрузки страницы.

Причина: `Login.tsx:38` делает `navigate('/', { replace: true })` (SPA-навигация React Router). Но защита роутов в `App.tsx` управляется собственным локальным стейтом `isAuthenticated` (`App.tsx:23`), который вычисляется **один раз** в `useEffect` при монтировании (`App.tsx:25-29`, зависимость `[]`) и никогда не пересчитывается после логина. `AuthContext.login()` обновляет статус только внутри самого контекста — а `App.tsx`, по уже известному техдолгу, вообще не использует `AuthContext` для роутинга.

Итог: сразу после "успешного" логина `App.tsx`'s `isAuthenticated` всё ещё `false` → маршрут `/` рендерит `<Navigate to="/login" />` → и `/login` тоже перечитывает тот же устаревший `false` → снова рендерит форму логина. Пользователя буквально отбрасывает назад.

Почему логаут и принудительный разлогин на 401 работают, а логин — нет: оба используют `window.location.href = ...` (полная перезагрузка страницы, `Layout.tsx` и `api/client.ts:34`), что заново запускает mount-эффект и подхватывает токен. Логин — единственное место, использующее SPA-навигацию вместо hard-reload.

## Что нужно

Либо (а) реально подключить `App.tsx` к `AuthContext` для роутинга (заодно закрывает известный техдолг), либо (б) минимально — сделать `window.location.href = '/'` после логина вместо `navigate()`, как уже сделано для логаута.
