# Приоритет задач инвертирован между mobile и web

Одно и то же числовое значение `priority` означает противоположный уровень важности на разных платформах:

- **Mobile** (`mobile/src/screens/TasksScreen.js:132-136`, кнопки `TasksScreen.js:1875`): `1 = высокий`, `3 = низкий` (`normPriority`).
- **Web** (`web/src/components/TaskModal.tsx:38-42`, `TaskCard.tsx:50-66`, `web/src/api/tasks.ts:75-86`): `1 = низкий`, `3 = высокий` — ровно наоборот.

`priority` хранится как обычное число в БД без enum/проверки на бэкенде (`backend/routes/tasks.js` пропускает как есть) — значит **любая задача, созданная на одной платформе, показывает противоположный приоритет на другой**. Это уже искажает реальные данные для пользователей, работающих с обеих платформ (сейчас это в первую очередь сам владелец).

## Что сделано

Web переведён на конвенцию mobile (`1=высокий, 3=низкий`): `TaskModal.tsx` (`PRIORITY_OPTIONS`), `TaskCard.tsx` (`getPriorityLabel`/`getPriorityClass`), `api/tasks.ts` (`priorityTextToNumber`, комментарий типа) — коммит `250bc4db` в `web`. Проверено вживую (Playwright): клик по кнопке "ВЫСОКИЙ" теперь отправляет в API `priority: 1`.

**Не сделано и стоит иметь в виду:** миграция уже существующих в БД задач, если какие-то были созданы через web со старой (неверной) конвенцией — до этой правки. Веб был в разработке, реальных пользователей кроме владельца не было, но стоит перепроверить фактические данные перед тем как считать вопрос полностью закрытым.
