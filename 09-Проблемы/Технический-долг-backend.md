# Технический долг — Backend

Собрано аудитом кода 2026-07-22. Отдельные пункты вынесены в свои заметки: [[IDOR-подзадачи]], [[JWT-секрет-фолбэк]].

## Логирование паролей в открытом виде
`server.js` (глобальный middleware) печатает **весь `req.body`** для любого запроса, включая `/login`, `/register`, `/reset-password` — пароли попадают в консоль/логи процесса (PM2 логи). Убрать или маскировать поля `password`/`newPassword` перед логированием.

## Хардкод админа по числовому userId
`routes/secretChat.js` — все проверки прав `Number(req.userId) !== 4`. Хрупко: переносится на другую БД/окружение — сломается, нигде не задокументировано, кроме кода. Стоит хотя бы вынести `4` в переменную окружения `ADMIN_USER_ID`, если не делать полноценную ролевую модель (сама фича — неформальная "пасхалка", возможно не стоит усилий полноценной ролевой системы).

## Ошибки БД пробрасываются клиенту
В части мест (`err.message`, а в `habits.js POST /` — ещё и `err.sqlMessage`) детали SQL-ошибок уходят в ответ 500 клиенту — раскрытие структуры схемы/запросов.

## TLS без проверки сертификата в email-сервисе
`emailService.js`: `tls: { rejectUnauthorized: false }` с комментарием "для тестирования, можно убрать позже" — стоит убрать на проде или явно обосновать, почему остаётся.

## Хардкод прод-IP в приветственном письме
`getWelcomeEmailHtml` содержит ссылку на `https://85.198.96.149` вместо домена `mindandmotion.ru` — рассинхрон с остальным кодом, где используется домен.

## Мёртвые таблицы БД
Создаются в `initDB.js`, но ни один route их не использует: `chat_settings`, `secret_chat` (старая версия таблицы чата), `message_reactions`, `email_logs`. Колонки без использования: `folders.emoji`, `birthdays.type`, `birthdays.notify_before`. `announcement_reads` не имеет уникального/первичного ключа, хотя код полагается на `INSERT IGNORE` для идемпотентности — реально не защищает от дублей.

## Дублирующиеся способы изменения одной сущности
Задачу можно удалить через `DELETE /api/tasks/:id` **и** `POST /api/tasks/delete`; запись привычки — через `DELETE /records` (body) и `DELETE /records/:habit_id/:year/:month/:day` (params). Не баг, но стоит консолидировать при следующем рефакторинге этой области.

## Происхождение таблицы `users` неизвестно
`initDB.js` не создаёт `users` — только читает/ALTER-ит. Реальная DDL не найдена в репозитории (возможно, применена вручную на проде когда-то, миграции не сохранились). Нужно либо найти историческую миграцию, либо задокументировать текущую структуру вручную через `DESCRIBE users` на проде и добавить `CREATE TABLE IF NOT EXISTS users` в `initDB.js` для воспроизводимости на новом окружении.

## Дублирование email-шаблонов
`emailService.js` содержит готовые функции `getVerificationEmailHtml`/`getWelcomeEmailHtml`, но `routes/auth.js` не использует их — вместо этого дублирует свой HTML инлайн в каждом роуте.
