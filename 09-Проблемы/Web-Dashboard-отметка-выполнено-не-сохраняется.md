# Отметка задачи выполненной с Dashboard не сохраняется

Владелец отметил 2 задачи выполненными прямо с дашборда — не сохранилось. Также: включение "Показывать выполненные" на странице Задач ничего не показывает.

## Причина (найдена в коде, тот же класс бага, что и [[Web-Фокус-сессия-портит-задачу]])

`Dashboard.tsx:100-112` (`handleTaskToggle`) вызывает `updateTask(taskId, { done: !currentDone })` — **частичный** payload с одним полем. `adaptTaskForAPI` (`api/tasks.ts:145-181`) не имеет фолбэка для `title` (в отличие от всех остальных полей, у которых есть `|| null`/`|| 0`) — значит `title` остаётся `undefined`, и при `JSON.stringify` ключ `title` пропадает из тела запроса целиком.

На бэкенде (`backend/routes/tasks.js:343-367`, `PUT /:id`) `title` из `req.body` деструктурируется без фолбэка и идёт прямо в параметры SQL-запроса — `mysql2` кидает исключение на `undefined` в bind-параметрах ("Bind parameters must not contain undefined"). Запрос падает с 500, пойманным пустым `catch` в `Dashboard.tsx` (`console.error` без сообщения пользователю) — `done` никогда не долетает до БД.

Это объясняет оба симптома сразу: задачи не отмечаются выполненными (500 на каждой попытке), и "показывать выполненные" ничего не показывает, потому что выполненных задач в БД реально нет.

**Сравнение:** `Tasks.tsx:handleToggleTask` (270-331) уже делает это правильно — передаёт ВСЕ поля задачи, включая `title`, плюс вычисляет `nextDate` для рекуррентных задач. Баг только в отдельной, более простой реализации на Dashboard.

## План фикса (на завтра)

Привести `Dashboard.tsx:handleTaskToggle` к тому же паттерну, что `Tasks.tsx:handleToggleTask` — передавать полный набор полей задачи, а не только `done`. Заодно стоит рассмотреть системный фикс: добавить на бэкенд отдельный `PATCH`/частичный update-эндпоинт (как уже сделано для focus — `POST /tasks/:id/focus`), чтобы не приходилось тащить все поля с фронта каждый раз, когда меняется одно.

## Смежное — стоит перепроверить

[[Web-Повтор-задач-не-работает]] — рекуррентность могла не сработать именно из-за этого бага (если тестировали через дашборд, запрос падает ещё до того как доходит до логики пересоздания задачи на бэкенде), а не потому что сама логика рекуррентности сломана.
