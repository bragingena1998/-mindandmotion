# Mobile — текущее состояние

> Источник — реальный код `E:\ProjectMM\mobile` на 2026-07-22. Старые доки (docs/, .agent/wiki/mobile-screens.md) не использовались как истина.

## Навигация

Реальная навигация задаётся **в `App.js` инлайн**, а не в `src/navigation/` — там лежит `AppNavigator.js`, который **не импортируется и не используется** (мёртвый код, только 3 таба Tasks/Habits/Profile, не совпадает с реальной структурой). Актуальные табы (`createBottomTabNavigator` в `App.js`): **Tasks**, **Habits**, **Dashboard** (центральная кнопка). Calendar/Profile как отдельные `<Tab.Screen>` не подтверждены на 100% при аудите (файл частично усечён) — при следующей ревизии стоит дочитать `App.js` целиком. Секретный экран — тройной тап по профилю → `SecretChatScreen`.

`app.config.js` (не `app.json` — его физически нет) задаёт плагины: `expo-build-properties`, `expo-notifications`, `expo-secure-store`, `expo-localization`, `expo-sqlite`.

## Офлайн-режим и синхронизация

**Подтверждено: переход на `expo-sqlite` реально завершён и используется в проде** (Tasks/Habits/Dashboard/Settings через `useLocalFirst`, Calendar — напрямую через `cacheManager`). История "MMKV → SQLite" (см. [[История-решений]]) подтверждается кодом.

Слои:
- `utils/sqliteCacheManager.js` — низкоуровневый класс над `expo-sqlite` (таблица `cache`, WAL-режим, in-memory Map поверх).
- `utils/cacheManager.js` — прикладной слой: `setTasks/getTasks`, `setHabits/getHabits`, `setHabitRecords`, `setFolders`, `setDashboard`, `setUser`, `setStats`, `setSettings`, TTL-синхронизация 5 минут.
- `utils/syncQueue.js` — таблица `sync_queue`, `enqueue/getAll/remove/clear/flush()`. Реализует **tempId→realId** паттерн: `temp-<timestamp>` заменяется на реальный id сервера после успешного POST.
- `hooks/useLocalFirst.js` — универсальный хук: мгновенно отдать кэш → в фоне дёрнуть сеть → перезаписать кэш; optimistic update/rollback; `NetInfo`-триггер `syncQueue.flush()` при восстановлении сети; `AppState`-триггер тихой синхронизации.

⚠️ **Мёртвый остаток старой миграции**: `utils/tasksCache.js` импортирует `react-native-mmkv`, которого **нет ни в package.json, ни в node_modules** — файл нигде не импортируется, но физически лежит в репозитории и упадёт при попытке использования. См. [[Технический-долг-mobile]].

`DataSyncContext` — **не менеджер синхронизации**, вопреки названию: это просто `tick`-счётчик + `bumpAll()` для форс-ререндера. Реальная синхронизация — целиком в `syncQueue`/`useLocalFirst`.

## Авторизация и хранение токена

⚠️ **Расхождение со старой документацией и с `.windsurf/rules/02-mobile.md`**: auth-токен хранится в **`AsyncStorage`** (`services/storage.js`, ключи `app-auth-token`/`app-user-id`), **не в SecureStore**, вопреки тому, что написано в старых правилах ("SecureStore, не AsyncStorage!"). SecureStore реально используется только для **PIN-кода блокировки приложения** (`services/appLock.js`, хэш+соль). Биометрия — `expo-local-authentication`.

Найден баг: `AppLockScreen.js` импортирует `secureGet` из `appLock.js`, но там эта функция **не экспортирована** — тихий сбой (проглочен `catch{}`), из-за чего длина PIN всегда дефолтная (4). См. [[Технический-долг-mobile]].
