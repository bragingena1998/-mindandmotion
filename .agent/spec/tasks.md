# Шаблон постановки задачи агенту

> Используй этот шаблон когда ставишь задачу Windsurf/Kimi.
> Заполни все поля — это резко снижает количество итераций и переделок.

---

## Шаблон: Новая фича

```
ПЛАТФОРМА: [web / mobile / backend]
ВЕТКА: [web-review / mobile-dev3.0 / backend]

ЗАДАЧА:
[Одно предложение — что нужно сделать]

КОНТЕКСТ:
[Зачем это нужно, какую проблему решает]

ФАЙЛЫ ДЛЯ ЧТЕНИЯ:
[Список файлов, которые надо прочитать перед началом]

РЕФЕРЕНС ИЗ МОБИЛКИ (если есть):
[Экран/компонент из mobile-dev3.0, логику которого переносим]

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
[Конкретное описание что должно работать]

ОГРАНИЧЕНИЯ:
[Что нельзя трогать / ломать / изменять]

ПРИОРИТЕТ: [высокий / средний / низкий]
```

---

## Шаблон: Багфикс

```
ПЛАТФОРМА: [web / mobile / backend]
ВЕТКА: [web-review / mobile-dev3.0 / backend]

ФАЙЛ(Ы): [где баг]

ФАКТИЧЕСКОЕ ПОВЕДЕНИЕ:
[Что происходит сейчас]

ОЖИДАЕМОЕ ПОВЕДЕНИЕ:
[Что должно происходить]

ШАГИ ВОСПРОИЗВЕДЕНИЯ:
[Как воспроизвести баг]

ВЕРОЯТНАЯ ПРИЧИНА (если известна):
[]

ОГРАНИЧЕНИЯ:
[Что нельзя трогать]
```

---

## Шаблон: Перенос фичи mobile → web

```
ФИЧА: [название]
ВЕТКА: web-review

ИСТОЧНИК (mobile):
- Экран: [src/screens/XxxScreen.js]
- Компонент: [src/components/Xxx.js]
- Логика: [описание ключевых функций]

ЧТО ПЕРЕНЕСТИ:
- [ ] Структура данных
- [ ] API-вызовы
- [ ] UI-компонент
- [ ] Логика отображения (статусы, вычисляемые поля)
- [ ] Оптимистичный UI

ОТЛИЧИЯ WEB ОТ MOBILE:
[Что нужно адаптировать — например, RN-жесты → CSS hover/drag]

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
[]
```

---

## Шаблон: Рефакторинг

```
ФАЙЛ(Ы): []
ЦЕЛЬ: [что улучшить — читаемость / производительность / дублирование]

ЧТО НЕЛЬЗЯ МЕНЯТЬ:
- Внешний API (пропсы компонентов)
- Поведение для пользователя
- Имена экспортируемых функций

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
[]
```
