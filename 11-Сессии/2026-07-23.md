# Сессия 2026-07-23 — реструктуризация vault, инцидент с секретами, деплой backend, TG-бот → Remote Control, старт аудита web

## Что сделано

- Продолжили начатую вчера реструктуризацию: `docs/` и `docs-v2/` официально свёрнуты, `vault/` — единственный источник правды (закреплено в `CLAUDE.md`).
- Подключили `landing/` как полноценный git submodule (раньше жил отдельно, не в структуре репозитория).
- Синхронизировали `backend`/`mobile`/`web`/`vault`/`docs` — локальные несохранённые изменения приведены в порядок и запушены.
- Нашли и закрыли **критический инцидент безопасности**: при переименовании локальной ветки суперпроекта (`landing` → `meta`) секреты из `context-perplexity/` на несколько минут оказались на публичном GitHub. Ветка удалена владельцем, история переписана (`git filter-branch`), папка добавлена в `.gitignore`, все затронутые секреты в тот же день сменены (`DB_PASSWORD`, `JWT_SECRET`, `EMAIL_PASS`, `GROQ_API_KEY`, личный пароль почты).
- Заодно нашли и исправили: небезопасный хардкод-фолбэк `JWT_SECRET` в коде backend; дважды — повреждённую (UTF-16 вместо UTF-8) кодировку `.gitignore` в `backend/` и `tg-bot/`, из-за которой `.env` реально не игнорировался, несмотря на видимость защиты.
- Создали отдельную ветку `meta` в общем репозитории на GitHub — теперь у корневого `CLAUDE.md`/`docs-v2` тоже есть backup, не только у submodule'ов.
- **Деплой backend на прод**: обнаружили, что git на VPS не имел общего предка с GitHub (`unrelated histories`) — история переинициализирована на сервере когда-то раньше. Сделали полный бэкап, пересобрали git-репозиторий на сервере с нуля (чистый `git clone` с GitHub), сверили содержимое файлов построчно — реальных расхождений было всего 2 (`initDB.js` — новые таблицы/миграции, `server.js` — CORS wildcard→allowlist), всё остальное оказалось шумом CRLF/LF. Задеплоено и проверено живыми curl-запросами.
- **Инцидент, обнаруженный при деплое**: backend не может подключиться к MySQL (`kukopoocheypot.beget.app:3306`) — `Connection refused` на уровне TCP. Похоже, спровоцировано сменой пароля БД (старый процесс долбился неверным паролем, вызвал автоблокировку IP на стороне Beget). Написали в поддержку Beget с точными шагами воспроизведения — ждём ответа.
- Исследовали идею голосового Telegram-моста для удалённой работы (надиктовать голосовое → задача → отчёт). По ходу обсуждения проверили нативный **Remote Control** у Claude Code — работает, двусторонний, кнопки-подтверждения кликабельны с телефона. Решили не строить кастомного бота — заменили на Remote Control + правила автоотчётов (утро/вечер) в `CLAUDE.md`. `tg-bot/` архивирован (ветка удалена с GitHub, локальная папка помечена архивом).
- Начали планировать миграцию `web/` (v2 сайта) до паритета с мобильным приложением. Аудит текущего состояния: Login/Dashboard/Tasks/Habits — готовы; Calendar/Profile/SecretChat/Register — заглушки; ForgotPassword/NotificationSettings/AppLock/Settings — отсутствуют полностью. Согласован порядок: AuthContext-фикс → Calendar → Profile/Settings/NotificationSettings → Register/ForgotPassword → SecretChat/AppLock (в самом конце).
- Провели первый визуальный аудит `web/` (поставили Playwright, т.к. `chromium-cli` не было в системе) — нашли 2 подтверждённых бага в обработке ошибок API (см. ниже).

## Новые решения (ссылки на 08-Решения)

- vault — единственный источник правды, `docs/`/`docs-v2/` — архив.
- Суперпроект получил собственную ветку `meta` на GitHub (не создавать новый отдельный репозиторий).
- Голосовое управление — через нативный Remote Control, а не через кастомный Telegram-бот.
- Порядок миграции web/v2 — см. выше, зафиксирован по согласованию с владельцем.
