## Dashboard — подробно (опровержение старой документации)

Полностью реализованные, рабочие виджеты с реальными API-данными:
1. **Задачи на сегодня** — просроченные/сегодня/завтра, оптимистичный тоггл, empty-state.
2. **Привычки на сегодня** — тоггл выполнения кликом, счётчик done/total.
3. **Статистика** — 4 метрики (запланировано/выполнено сегодня/`calculateStreak()`/активные привычки). ⚠️ `calculateStreak()` на деле считает % выполнения на сегодня, не streak по дням подряд — неточный нейминг.
4. **Неделя** — столбчатый график за 7 дней с цветовой индикацией.
5. **Ближайшее событие** — обратный отсчёт до ближайшей задачи с датой/временем.

## API-слой (`src/api/`)

`client.ts`, `tasks.ts`, `habits.ts`, `types.ts` (только реэкспорт). Модулей `auth.ts`/`profile.ts`/`calendar.ts` нет.

- Двусторонние адаптеры (`adaptXFromAPI`/`adaptXForAPI`) везде — защитные `??`-цепочки на случай разных вариантов имён полей.
- `habits.ts` парсит `days_of_week` в 4 возможных форматах (JSON-массив, Postgres-литерал `{1,2,3}`, CSV-строка, число) — признак нестабильного контракта бэкенда за время эволюции схемы.
- Токен читается сразу из двух ключей (`app-auth-token` и `mm_token`) — легаси-дублирование, не убранное до конца. См. [[Технический-долг-web]].

## Контексты

- **`AuthContext.tsx`** — есть `user`/`isAuthenticated`/`login`/`logout`, но **`App.tsx` его не использует** для проверки авторизации — держит свой отдельный `useState`, читает токен из localStorage напрямую. Рассинхрон: после `logout()` из контекста `App.tsx` не узнает об этом без перезагрузки страницы. Плюс незакрытый `// TODO: Validate token and get user info` — токен не валидируется, юзер не подгружается при монтировании. См. [[Технический-долг-web]].
- **`BannerContext.tsx`** — используется по назначению и полностью: единый плавающий баннер-таймер для habit-timer и focus-session, переживает смену страниц (`Layout.tsx`, `GlobalTimerBanner.tsx`, `FocusModal.tsx`, `HabitTable.tsx`).
