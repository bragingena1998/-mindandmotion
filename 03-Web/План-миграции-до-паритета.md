## Login / Auth

Бэкенд (`backend/routes/auth.js`) полностью готов и используется mobile end-to-end: `/login`, `/register`, `/send-verification-code`, `/verify-code`, `/forgot-password`, `/reset-password`. Ничего из этого не нужно строить на бэкенде — только на web-фронте.

| Фича | Mobile | Web | Приоритет |
|---|---|---|---|
| Вход | Полный, + запоминание email | Есть, но см. [[Web-Логин-редирект-баг]] | P0 (баг) |
| Регистрация | 2 шага: форма → код с почты, чекбоксы согласий (privacy/terms обязательны, marketing опционально), демо-данные по умолчанию включены, после успеха — автовход + отдельный вызов `/policies/accept` | Буквально `<div>Coming soon</div>`, 0% | P0 |
| Забыл пароль | 2 шага: email → код + новый пароль, бэкенд рабочий | Отсутствует полностью — ни страницы, ни ссылки | P0 |
| Токен/авторизация — единый источник правды | — | `AuthContext` существует, но `App.tsx` его не использует (см. [[../03-Web/Технический-долг-web]]); `// TODO: validate token` так и не сделан | P1 |
| Текст ошибки логина | Читает и `.message`, и `.error` от бэкенда | Читает только `.message` — бэкенд всегда отдаёт `.error`, реальный текст ошибки (кроме неверных данных) никогда не доходит до пользователя | P1 |
| PIN/биометрия после входа | Полноценный app-lock: SHA-256+соль, grace period, биометрия, привязка к жизненному циклу приложения | Не существует и не обязана — другая парадигма (браузер, нет "сворачивания" в том же смысле) | P2/P3, отдельное проектирование, не прямой перенос |

## Dashboard

| Фича | Mobile | Web | Приоритет |
|---|---|---|---|
| Обработка сбоя загрузки | Офлайн-кэш (SQLite) — при сбое сети показывает последние известные данные | Молча показывает "всё выполнено" — см. [[Web-Dashboard-молчит-при-ошибке-API]] | P0 |
| "Запланировано сегодня" | Диапазонная логика (дата→дедлайн + просроченные) | Точное совпадение одного дня — см. [[Web-Dashboard-неверный-расчёт-запланировано]] | P0 |
| Тоггл привычки с дашборда | Понимает Дни/Часы/Количество/дневной план, корректный "следующий шаг" при тапе | Только бинарный тоггл (создать/удалить запись со значением 1) — для Часов/Количества это неверно | P0 |
| Виджет дней рождений/событий | Есть, с подсчётом "через N дней", переходом на новый год | Отсутствует полностью | P1 |
| Лимит привычек в списке | Показывает все активные | Жёсткий `.slice(0,5)` без "показать ещё" | P1 |
| Подзадачи с дашборда | Бейдж + модалка прямо с карточки задачи | Не показывается, хотя `subtasksCount` уже приходит с бэкенда | P1 |
| Сохранение таймера привычки прямо с дашборда | Есть отдельный баннер с кнопкой "Сохранить" | Нет такого действия с дашборда | P1 |
| Офлайн-кэш данных дашборда | SQLite | Нет вообще | P2 |
| Кнопка ручного обновления | Pull-to-refresh | Нет способа обновить без перезагрузки страницы | P2 |
| Приветствие по времени суток | 4 диапазона, покрывают все 24 часа | 3 диапазона — с 18:00 до 5 утра всегда "добрый вечер" | P3 |
| Toast при выполнении/отмене задачи | Есть | Нет, только CSS-анимация | P3 |

## Задачи

Бэкенд поддерживает больше, чем web сейчас использует: `/tasks/overdue`, `/tasks/:id/stop-recurring`, `/tasks/:id/focus`, `/tasks/stats` — всё это уже готово и ждёт, пока web начнёт их вызывать.

| Фича | Mobile | Web | Приоритет |
|---|---|---|---|
| Приоритет задачи | — | Инвертирован относительно mobile — см. [[Web-Приоритет-задач-инвертирован]] | P0 (данные) |
| Фокус-сессия — сохранение | Атомарный `/tasks/:id/focus` | Общий `updateTask`, может стереть поля — см. [[Web-Фокус-сессия-портит-задачу]] | P0 (данные) |
| Просроченные задачи из прошлых месяцев | Отдельный запрос `/tasks/overdue`, всегда видны | Пропадают при смене месяца — точь-в-точь баг, который на mobile уже когда-то чинили | P0 |
| Остановить повторение рекуррентной задачи | Кнопка, вызывает `/tasks/:id/stop-recurring` | Нет такой кнопки вообще — рекуррентную задачу нельзя сделать разовой | P1 |
| Ошибка загрузки | Alert с текстом от сервера | Сырой `err.message` прямо в UI, без перевода и без кнопки повтора (в отличие от Привычек) | P1 |
| Управление папками (создать/переименовать/удалить/сортировка) | Полный набор + drag&drop задачи в папку | Только выбор существующей папки в модалке задачи — создать/удалить/переименовать негде | P1 |
| Недельная/месячная статистика | Считается на бэкенде (`/tasks/stats`) | Считается на клиенте неправильно (только по видимому месяцу, путает `date`/`doneDate`) — цифры между платформами могут не совпадать | P2 |
| Drag&drop задачи в папку | Полноценный жестовый drag с подсветкой зоны сброса | Нет (ожидаемо для мышки/тача — но и быстрого "переместить в папку" действия из карточки тоже нет) | P2/P3 |

## Привычки

Схема БД не имеет колонки `active` — фильтр `active !== false` на web ничего не делает (бэкенд никогда не возвращает это поле), но это "мёртвая мина" на будущее.

| Фича | Mobile | Web | Приоритет |
|---|---|---|---|
| Таймер для привычек-"Часы" | Корректно суммирует | ~60-кратная ошибка — см. [[Web-Таймер-привычек-часы-баг-60x]] | P0 (данные) |
| Кнопка "Удалить" привычку | Есть только "Архивировать" | Есть и "Удалить", и "Архивировать" как раздельные действия — но `DELETE /habits/:id?year&month` на бэкенде **всегда** архивирует, если переданы year/month — "Удалить" на деле ничего не удаляет, вводит в заблуждение | P1 |
| Ретроактивность изменения дней недели для прошлых месяцев | Применяет фильтр по дням недели ко всем месяцам одинаково, включая прошлые | Специально не применяет фильтр по дням недели к прошлым месяцам (эвристика "раньше текущего = архив") — платформы дают разный процент выполнения по одним и тем же данным | P1 (нужно осознанное решение, не автоматический фикс) |
| `target_type: monthly` | Не существует как отдельный вариант (только daily/period) | Есть третий вариант в UI, но нигде в коде не отличается от `period` — путает без всякой пользы | P2 |
| Debug-логи в продакшене | — | `console.log` внутри цикла рендера ячеек таблицы + несколько в `habits.ts` — лишняя нагрузка и потенциальная утечка данных в консоль | P2 |
| Офлайн-очередь для мутаций привычек | `syncQueue`/`cacheManager` | Нет вообще — полный рефетч после каждой мутации | P2 |
| Сворачиваемый блок "доп. настройки" в форме привычки | Есть (скрывает даты/дни недели, если не заданы) | Все поля всегда развёрнуты | P3 |

## Что уже в порядке (не трогать, не переделывать зря)

- Trend-график привычек — данные и таймфрейм полностью совпадают между платформами, web даже визуально приятнее.
- Ручной ввод значения для привычек-"Часы" (не через таймер) — на web корректно ведёт себя как edit-in-place.
- Копирование подзадач при завершении рекуррентной задачи — логика на бэкенде, платформонезависима, будет работать сразу, как только web начнёт поддерживать "остановить повторение".
- Глобальный баннер фокус-сессии/таймера привычки на web (`BannerContext`/`GlobalTimerBanner`) — переживает переход между страницами не хуже, чем на mobile.
