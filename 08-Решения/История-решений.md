## Backend — решения

- Все API-роуты под `/api`, включая auth (`/api/login`) — устойчиво, подтверждено кодом.
- Токен — JWT в `Authorization: Bearer`.
- Часовые пояса: БД и API — UTC (`timezone: '+00:00'` в пуле MySQL), конвертация в локальное время только на клиенте.
- Эмодзи-поля — обязательна кодировка `utf8mb4` (иначе превращаются в `?`).
- Архив привычек — через `habit_monthly_configs` + `is_archived`, а не удаление.
- Офлайн-режим на мобиле спроектирован **поверх** существующей MySQL-схемы (SQLite-кеш + `sync_queue`), а не как переписывание бэкенда.
- Регистрация: добавлены `privacy_accepted`, `terms_accepted`, `email_marketing_accepted`, `policies_accepted_at`, таблицы `app_announcements`/`announcement_reads`.

Текущее состояние (проверено кодом) — [[01-Backend/Текущее-состояние]]. Известные проблемы — [[Технический-долг-backend]], [[IDOR-подзадачи]], [[JWT-секрет-фолбэк]].

## Web — решения

- Паттерн API-модуля: `api/[module].ts` (типы + `adaptFromAPI`/`adaptForAPI` + CRUD) → `pages/[Module].tsx` → `components/` → `styles/`.
- От полной перезагрузки (`await loadData()`) после мутации — к точечным оптимистичным обновлениям (иначе дашборд "мигал" при отметке привычки).
- Глобальный баннер-таймер вынесен в `BannerContext` — не терять таймер при смене вкладок.
- Хардкод-цвета переведены на CSS-переменные под систему тем.
- Сортировка привычек: desktop — нативный HTML5 drag-and-drop, mobile — кнопки ▲/▼ (drag на мобиле отклонён).
- `daysOfWeek`: индекс `Date.getDay()` (0=Вс…6=Сб), пустой массив = "все дни активны", фильтровать только текущий/будущие месяцы.
- Правило по итогам самого мучительного бага (`daysOfWeek`, см. ниже): "при наличии бэкенда в репо — сначала читать его код, не строить гипотезы на фронтенде".

Текущее состояние — [[03-Web/Текущее-состояние]] (подтверждает: Dashboard полностью реализован, вопреки старой документации). Технический долг — [[Технический-долг-web]].

## Mobile — решения

- Drag&drop задачи в папку: `PanGestureHandler` (всегда enabled) снаружи, `LongPressGestureHandler` внутри; координаты чипов — через `setTimeout(50ms)`.
- Toast вместо `Alert` при drop в папку.
- Эволюция локального хранилища для офлайна: **MMKV** (заявлена причина — "в ~30 раз быстрее AsyncStorage") → сборка падала на Gradle/Kotlin несовместимостях нативного модуля → переход на **`expo-sqlite`**. **Подтверждено свежим аудитом кода (2026-07-22): переход на SQLite реально завершён и используется в проде**, MMKV остался только как мёртвый неиспользуемый файл — см. [[02-Mobile/Текущее-состояние]] и [[Технический-долг-mobile]].
- Обновления — OTA (`eas update`) для JS-правок, полная пересборка только при нативных модулях.

## Инфраструктура и деплой

- VPS Beget, backend в `/var/www/backend`, PM2-процесс `mindandmotion-backend`.
- Домен `mindandmotion.ru`, HTTPS через Certbot (только для домена без `www` — для `www` подсказка сертификата не получилась, обошли).
- Реальный конфиг сайта — `sites-enabled/default`, а не отдельный файл (важно помнить при следующем инфра-инциденте).
- **Продовый инцидент**: 502 на весь `/api/*` после рестарта VPS — причина рассинхрон портов (nginx проксировал на 5000, PM2-бэкенд слушал 3000). Смотри [[01-Backend/Текущее-состояние]] — сейчас дефолт в коде 3000, `PORT` в `.env` вообще не задан. Этот же класс проблемы может повториться, если кто-то поменяет один из двух портов, не тронув второй.
- Решение не деплоить фронт через git на сервере — собирать локально, заливать `dist/` через `scp`.

Раннбуки — [[10-Раннбуки/deploy-backend]], [[10-Раннбуки/deploy-web-vps]], [[10-Раннбуки/rollback]].
