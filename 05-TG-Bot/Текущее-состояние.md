# TG-Bot — АРХИВ (заменён на Remote Control)

**2026-07-23: проект моста закрыт.** Владелец обсудил реализацию голосового управления через Telegram (транскрипция голосовых → задача → отчёт), но по ходу обсуждения и живого теста выяснилось, что встроенный **Remote Control** Claude Code (мобильное приложение Claude, вкладка Code) закрывает исходную цель — работу с проектом с телефона, живой двусторонний диалог, интерактивные подтверждения (проверено на `AskUserQuestion` — кнопки реально кликабельны с телефона) — без необходимости строить и поддерживать отдельного бота.

**Что сделано при закрытии:**
- Ветка `tg-bot` удалена с GitHub (2026-07-23, восстановима по SHA).
- Локальная папка `E:\ProjectMM\tg-bot` оставлена как есть (не удалена, не перемещена) — помечена архивом в `tg-bot/README.md` и корневом `CLAUDE.md`.
- Единственный оставшийся открытый вопрос — отчёты по расписанию (утро/вечер), которые Remote Control не делает сам (нужна активная сессия). Решение: правило в `CLAUDE.md` — генерировать эти отчёты по приветствию/прощанию владельца в начале/конце сессии, а не по реальному будильнику.

**Что технически годно к переиспользованию, если понадобится voice-интеграция где-то ещё:** `scripts/transcribe-voice.js` — самодостаточная, рабочая интеграция с Groq Whisper (`whisper-large-v3-turbo`, русский язык), протестирована живьём 2026-07-23 (`scripts/voice-echo.cjs`, временный тестовый скрипт, тоже оставлен в репозитории).

## Как это было устроено (историческая справка)

> Мост Telegram ↔ Windsurf ↔ (опционально) Perplexity, плюс approve-gate для опасных операций. Спроектирован под старый workflow (см. [[90-Архив/old-workflow/Индекс]]), но сам механизм подтверждения перед риском остаётся актуальным принципом независимо от инструмента.

## Что это делает по факту кода

Двусторонний конвейер: голос/текст в Telegram → `scripts/telegram-bridge.cjs` пишет задачу в `windsurf-task.md` → `scripts/watch-task.ps1` (polling раз в секунду) триггерит Windsurf → результат уходит обратно в Telegram через `scripts/notify-tg.cjs` (с декодированием CP866→UTF-8 — легаси-фикс кракозябр).

Approve-gate — обёртки над рискованными командами, каждая требует подтверждения кнопкой в Telegram перед выполнением: `git-push-safe.ps1`, `safe-deploy.ps1`, `safe-install.ps1`, `safe-migrate.ps1`, `safe-delete.ps1`, универсальный `approve.ps1`/`telegram-approve.cjs`.

Команды в Telegram: `/help`, `/status`, `/run [text]`, `/push [msg]`, `/deploy`.

## Технические заметки

- В `tg-bot/` **нет `package.json`** — запуск полностью через `node scripts/*.cjs` и `.ps1` напрямую, без npm-скриптов.
- `.env` (нужен для `TG_BOT_TOKEN`, `TG_CHAT_ID`, `GROQ_API_KEY`) в дереве не найден на момент проверки — либо в `.gitignore`, либо не создан локально.
- См. [[Технический-долг-tgbot]] — нет единой команды запуска всего конвейера.

## Известные грабли из истории (см. [[История-решений]])

Кракозябры кириллицы в CMD (CP866 vs UTF-8) — решены. `FileSystemWatcher` пропускал события на Windows — заменено на polling. Блокирующий `await` в polling loop мешал реагировать на кнопку Approve — решено переводом обработчиков в fire-and-forget. Два параллельных бота конфликтовали за один токен — решено (используется только `telegram-bridge.cjs`).
