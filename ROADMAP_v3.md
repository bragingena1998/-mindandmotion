## ✅ Этап 9: Офлайн-режим (Local-First)
> Приоритет: 🔴 Высокий | **✅ Завершён** (03.04.2026)

### Суть
Приложение работает без интернета. Данные читаются из локального SQLite-кэша, изменения накапливаются в очереди и автоматически синхронизируются при появлении сети.

### Новые файлы
- [x] **`src/utils/sqliteCacheManager.js`** — низкоуровневый SQLite-менеджер, создаёт таблицы `cache` и `sync_queue`
- [x] **`src/utils/cacheManager.js`** — хелперы: `getTasks/setTasks`, `getFolders/setFolders`, `getHabits/setHabits`, `getBirthdays/setBirthdays`
- [x] **`src/utils/syncQueue.js`** — класс `SyncQueue`: `enqueue(method, url, data)`, `flush(api, callback)`, `getAll`, `remove`, `clear`
- [x] **`src/utils/useLocalFirst.js`** — хук local-first для привычек, содержит `NetInfo.addEventListener` → при `isConnected` вызывает `syncQueue.flush(api)`

### Что покрыто офлайн-режимом
| Экран | Действия |
|-------|---------|
| TasksScreen | createTask, updateTask, deleteTask, toggleTask, createFolder, updateFolder, deleteFolder, reorderFolders, toggleSubtask, addSubtask, deleteSubtask, updateSubtask |
| HabitsScreen | toggleHabitRecord |
| CalendarScreen | saveEvent (POST/PUT), deleteEvent |

### Ключевые паттерны
- **tempId** (`temp-${Date.now()}`) для оффлайн-создания задач — заменяется на `realId` после синхронизации через callback в `flush`
- **local-first загрузка** — сначала показывается кэш, потом обновляется с сервера (нет мерцания)
- **тихие ошибки** — `ERR_NETWORK` не показывается пользователю, попадает в очередь
- **`loadTasks` фильтрует `temp-*`** при получении данных с сервера — нет дублей

### 🗄️ БД (SQLite — локально на устройстве):
```sql
CREATE TABLE IF NOT EXISTS sync_queue (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  method    TEXT NOT NULL,
  url       TEXT NOT NULL,
  data      TEXT,
  createdAt INTEGER
);
```
